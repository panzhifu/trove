- 诊断（用户报「切换视图有点卡顿」）：`set_view_mode` 里 `generation += 1` 是根源——generation 是所有数据缓存键（explorer snapshot、folders 全扫描、tag_counts、filter_exts、title_cache、workspace DataKey），视图切换明明只改展示形状，却被当成「库变了」：下一帧同步重跑 data pass（SQL 页查询 + 200 次 cell_from_asset stat）、explorer 的 4+N 个 COUNT（live/trash/recent/fonts + 每集合 count_assets）、400ms 后 arm_total_settle 再来一轮带 COUNT 的 data pass。

## 滑条拖不动修复（2194a1c，已推送）
- 🔴 **根因：render 每帧无条件 `set_value` 覆盖 SliderState** —— 播放中解码循环每帧 notify → render 每帧把拖动中的把手拉回外部值 =「滑条不能滑动」（暂停时 render 不跑所以能拖，是个鉴别特征）。修法 = **diff 同步**：`synced_position`/`synced_volume` 字段记上次推送值，外部值真变了才 set_value（position 阈值 0.5ms、volume 用 EPSILON）。这个坑对所有「entity-state 组件 + 高频 notify 的宿主」都成立，gpui-kit slider/state 没有 dragging 暴露（私有字段），diff 是唯一干净解。
- 顺手修：暂停时拖进度条 Release 立即写 `position_ms`（原来只写 seek_to）—— audio pipe 从 `position_ms` 重建，否则暂停拖动→恢复播放声音会从拖动前位置开始，音画错位。
