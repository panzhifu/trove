## 晚间 XVII：全屏跳帧 = 开环节奏漂移（已修）
- 根因：解码循环原来是「读完一帧 → `sleep(frame_ms/speed)`」的**开环**节奏 —— 每帧的**工作耗时会被加到周期里**（读帧+转 RGBA+纹理上传+主线程 `weak.update`/`notify`），而且 `as u64` 把 16.67ms 截成 16ms。全屏时每帧绘制更贵 → 主线程 hop 更慢 → 周期被拉长 → 画面整体慢于文件时间轴，观感就是跳帧/顿挫。
- 修法：改成**截止时刻制**（`due += period; sleep_until(due)`），落后时不睡（`pending` 只留最新帧 = 自动丢晚帧追赶），暂停/seek/重开 pipe 时重新锚定 `due`。
- 参照物对比（本机 mpv v0.41.0 + libplacebo）：mpv 是 **PTS/显示时钟驱动呈现**（`--video-sync=audio|display-resample`）、**`--framedrop` 显式丢晚帧**、**hwdec 硬解 + dmabuf 零拷贝**、GPU 渲染；我们仍是无 PTS、CPU 解码 + 每帧 CPU→GPU 上传 —— 节奏修好，架构级差距（硬解/零拷贝）仍在。

## 晚间 XVIII：借鉴 mpv —— 音频钟为主 + 丢晚帧
- 🔴 **rodio `Sink::get_pos()` 不能当绝对时钟**：`append` 时每个 source 都 `.track_position()`，periodic_access 把 `controls.position` 设成**当前 source 内**的位置 —— 我们按 100ms 分块喂，它每块都从 ~0 重新开始（源码 sink.rs:110-145）。
- 实现（mpv `--video-sync=audio` + `--framedrop` 的等价物）：
  - 音频循环重建时钟：`reading = base_ms + (appended - sink.len()) * 100ms + sink.get_pos()`（`len()` 含正在播的那块，故不重复计数），随 `Instant` 一起发布到 `audio_clock`；暂停/换 pipe（seek、速度、循环回绕）时置 `None`。
  - 视频循环每个快照读 `audio_clock_ms()`（**用经过的墙钟外推**，避免音频循环阻塞在 100ms 读块时给出过期值）：帧早于钟 → 等到 `pts - 8ms`；晚超过 `1.5 × frame_ms` → **丢弃该帧**（但时间轴照常前进）；无音频/暂停时回落墙钟截止制。
- 参数：`AUDIO_CHUNK_MS=100`（须与 core 的 `AUDIO_CHUNK_BYTES` 同步）、`SYNC_LEAD_MS=8`、`DROP_LATE_FRAMES=1.5`。
- 仍存差距：无 PTS（假定 CFR 用 `frame_ms` 推）、CPU 解码 + 每帧 CPU→GPU 上传（无 hwdec/零拷贝）、全屏时主窗口仍渲染。
