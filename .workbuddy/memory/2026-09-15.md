## 扩展连接失败诊断 + 中文化（用户报「no connection (start Trove)」）
- 根因：`collect.rs` 响应**无 CORS 头、不回 OPTIONS 预检**；扩展 popup 从 `moz-extension://` fetch 127.0.0.1 属跨域，Firefox MV3 host 权限默认不授予 → ping 被 CORS 拦；且 `POST /add` 的 octet-stream 必触发预检（404）→ 预检必死。跟 Trove 是否运行无关。
- 修复：collect.rs 统一给所有响应加 `Access-Control-Allow-Origin: *` + methods/headers（仅监听 127.0.0.1、只写 inbox，wildcard 可接受），新增 OPTIONS→204 分支；新增测试 `cors_headers_and_preflight`（4 个 collect 测试全过，TMPDIR 按 skill 约定）。
- 中文化：manifest name/description →「Trove 采集器」；右键菜单「保存图片到 Trove」「保存链接文件到 Trove」；通知与 popup 文案全中文，ping 失败信息带端口号与权限提示。
- ⚠️ 沙箱 curl 127.0.0.1 会被 http_proxy 劫持（返回 502 Bad Gateway 伪响应），`--noproxy '*'` 才是真直连；且沙箱与宿主网络隔离，根本看不到宿主的 Trove 服务——连接类问题只能靠代码分析或用户实测。
- 提交：改动被用户在真实终端的 `145942f`（3D axis overlays + update checker 大提交）收编，无需单独提交。工作区曾混有约 20 个文件的他项改动，提交前必须 git diff 确认归属。
