# 2026-09-06

## trove dock 标题搜索图标不显示 — 根因定位（已确认，未改代码）

- 症状：dock 面板标题栏的搜索按钮（`WorkspacePanel::title_suffix` 里的 `Button::icon(IconName::Search)`）不渲染。
- 排除项：图标资源链路全部正常——`gpui_kit::assets::Assets` 已注册、`search.svg` 存在、宏生成 path=`icons/search.svg`、gpui svg_renderer 走 `asset_source.load()` 可命中；Button/ButtonIcon/Icon 渲染链无问题；cargo check 通过。
- **根因**：`app.rs` 用 `DockLayout::tabs().panel(xxx)` 注册面板 = 裸 entity。gpui-kit 的 skin 需要 `PanelHandle`（presentation handle）才能调用 `title()`/`title_suffix()`；裸 entity 无法 downcast 出 handle（`PanelHandle::of` 返回 None）→ 标题退化为 `panel_name()` 静态文本，**`title_suffix` 永远不会被调用** → 搜索按钮整体不渲染。
- 源码证据：`gpui-kit crates/component/src/dock/panel.rs` 的 `panel_handle` 文档："Base's own `DockLayout::panel` ... store the bare entity, and a skin cannot recover presentation from one. Such a panel ... just draws its `panel_name` where its title would be." 且 `tab_panel.rs::panel_title` 会发 `tracing::warn`，但 trove 未初始化日志 subscriber，警告被静默丢弃。
- 用户侧验证：dock 中央标题显示的应是 "WorkspacePanel"（panel_name）而非 title() 返回的 "Assets"。
- 修复（已实施并编译通过）：`app.rs` import `panel_handle`，4 个面板全部改为 `DockLayout::tabs().panel_view(panel_handle(panel), cx)` 注册，用户确认图标已显示。

## 搜索弹窗不出现 — 第二个根因（已修复）

- 现象：搜索图标显示后，点击无弹窗。
- 根因：gpui-kit 的 `Root::render` 只挂 tooltip/menu overlay，**dialog/sheet/notification 三层需应用根视图自己挂载**（`Root::render_dialog_layer` 等是公开静态方法，官方 `story/examples/dock.rs` 与 `component-shell` 都在根视图 render 里 `.children(dialog_layer)`）。trove 没挂 → `open_dialog` 只写入 `Root.active_dialogs` 状态层，永不绘制。
- 修复：`AppView::render` 中取 `Root::render_dialog_layer/render_sheet_layer/render_notification_layer(window, cx)` 并作为根 div 的 children 追加。编译通过。

## 搜索后端增强（已实施，45 测试全过）

- **fts_query 重写**（assets.rs）：整串单短语 → 按空白拆词、每词转义为前缀短语 `"词"*`，FTS5 隐式 AND。实现多关键词 AND + 前缀匹配（前缀=词元以查询串开头，非子串）；语法字符仍全字面。
- **标签名进索引**：schema v3（SCHEMA_VERSION=3，FTS5 不能 ALTER，drop+recreate 加 `tags` 列），v2→v3 后空索引由 `Library::open` 的 backfill_search_on_migration 自动重建。
- **索引同步**：新增 `assets::fts_sync(conn, asset_id)`（delete+reinsert，含 tags_for_fts 查询）；tags.rs 的 add_to_asset / remove_from_asset / set_for_asset（批量后 sync 一次）/ delete（先收集受影响资产再级联删除+逐个 sync）都接上了；assets::update 改用 fts_sync。
- **build_where 的 LIKE text 条件**也扩展为含标签名（EXISTS join），使 query()/智能集合与 FTS 搜索语义一致。
- 新测试 4 个：fts_multi_term_is_and_and_prefix、fts_matches_tag_names_and_stays_in_sync、query_text_condition_matches_tag_names（store/mod.rs）、empty_fts_index_is_rebuilt_on_open（library.rs）；另有 fts_syntax_characters_stay_literal_after_refactor。
